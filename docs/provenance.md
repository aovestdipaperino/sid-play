# Provenance of rust-sid's data and constants

Audit date: 2026-11-12. Method: every file in src/, examples/, tools/, tests/
reviewed; GPL sources consulted only to identify matches, never to write code.
Paths are as of commit 6241dc3; since then `src/` moved to `crates/mos6581/src/` and
`examples/render.rs` to `crates/sid-play/src/main.rs`.

The GPL reference compared against is reSID 0.16 (the libsidplayfp/resid
repository at commit 81055e6, the last pre-1.0 import), whose filter, voice and
envelope design this crate follows, plus libsidplayfp for the power-on table.
Each finding is resolved one of three ways:

- **Public fact**: the value or structure is in a non-GPL public source (the MOS
  6581 datasheet, the C64 Programmer's Reference Guide, the C64 schematics, Bob
  Yannes' 1996 interview, a DSP textbook, Wikipedia). The source is named.
- **Own derivation**: derivable from first principles or from a public fact; the
  derivation is shown in one line. Rows for clean files say "no borrowed
  material".

Counts: the table has 43 data rows. 14 are Borrowed (5 "known", 9 "new"), 11 are
Public fact and 18 are Own derivation. A row with a mixed resolution ("Public
fact / own derivation") is counted once, under the first resolution named; 3
Public fact rows are mixed (the `filter.rs` topology row, the `filter.rs` routing
row and the `render.rs` row).
- **Borrowed**: matches a GPL source with no independent public source found.
  Where the match is, is recorded.

## Clean-room defaults

Without the `gpl-data` feature, `mos6581` reads these thirteen constants from
`crates/mos6581/src/clean_chip_data.rs`, derived only from public non-GPL
documents and own choices (full derivations are in that file). With the feature
they come from `sid-gpl-data`.

| Constant | Value | Source |
|---|---|---|
| `ENV_RATE_PERIOD` | `[8, 31, 63, 94, 149, 220, 267, 314, 392, 980, 1961, 3137, 3922, 11765, 19608, 31373]` | MOS 6581 datasheet, "Envelope Rates" table (Φ2 = 1.0 MHz); attack is 255 linear steps, so period = round(t_attack * 1 MHz / 255) |
| `ENV_EXPONENTIAL_BREAKPOINTS` | `[(255, 1), (104, 2), (52, 4), (26, 8), (13, 16), (6, 32), (0, 1)]` | Yannes interview (piece-wise linear approximation of an exponential) and the datasheet's 3x decay/release ratio; own breakpoints, a full sweep costs 767 rate periods, 3.008x a full attack |
| `ENV_RATE_COUNTER_SKIPS_ZERO` | `false` | unsourced own choice; a plain binary counter wraps through 0 |
| `EXTFILT_W0_LOW` | `1.0e5` | board 250466 R30 = 10 kOhm, C54 = 1 nF (project brief; the file says not independently verified, but the audit's `extfilt.rs` topology row above reads the same values off the fade0ff redraw of the 250466 schematic); w0 = 1/(R C), used uncompensated |
| `EXTFILT_W0_HIGH` | `100.0` | board 250466 C55 = 10 uF (project brief) with the datasheet's recommended 1 kOhm AUDIO OUT load (assumption); the audit's `extfilt.rs` topology row backs both from the redraw (C55 = 10uF, R31 = 1k to ground); w0 = 1/(R C) |
| `FILTER_Q_MIN` | `core::f64::consts::FRAC_1_SQRT_2` | datasheet register $17 ("16 resonance settings ... linearly"); "no resonance" taken as the Butterworth Q, own choice |
| `FILTER_Q_STEPS` | `8.0` | datasheet register $17 and the Yannes interview; own choice of range, Q(15) = 2.58 |
| `MIXER_DC` | `0.5` | Yannes interview (stopped-oscillator DC for volume playback); size and sign are an unsourced own choice |
| `VOICE_WAVE_ZERO` | `2048` | own reasoning: centred 12-bit DAC, real DAC offset not modelled |
| `VOICE_DC` | `0` | unsourced own choice; the DC is modelled once, in the mixer |
| `NOISE_OUTPUT_TAPS` | `[20, 18, 14, 11, 9, 5, 2, 0]` | oxyron.de SID register reference: noise assembled from bits 20, 18, 14, 11, 9, 5, 2 and 0 |
| `NOISE_CLOCK_BIT` | `19` | unsourced own choice, constrained by the Yannes interview ("an intermediate bit") and the datasheet noise range; slowest bit giving a shift rate of at least 40 kHz at the top setting |
| `NOISE_SHIFT_RELOAD` | `0x7F_FFFF` | unsourced own choice; all ones is a valid, maximally distant-from-lockup seed |

Other defaults used without the `gpl-data` feature:

- Combined waveform tables: the bitwise AND of the pure waveforms
  (`crates/mos6581/src/tables/default.rs`), our own derivation; the measured tables
  are used only with `gpl-data`.
- Filter cutoff: linear from 30 Hz to 12 kHz over the 11-bit register, the MOS 6581
  datasheet's nominal filter range ("approximately 30 Hz - 12 kHz"); the measured
  curves are used only with `gpl-data`.
- Power-on RAM pattern in `sid-play`: all zeros without `gpl-data`; libsidplayfp's
  captured pattern only with it.

## Known default-build fidelity gaps

The default build (without `gpl-data`) is clean-room and measurably less faithful
than the build with the measured data. The known differences:

- Cutoff closed corner: the default curve closes at 30 Hz (datasheet nominal, 2200
  pF) while the measured curve closes at about 200 Hz. Tunes and fixtures that play
  through a mostly closed low-pass come out much quieter in the default build. The
  scale fixture renders at rms 53 in the default build and 1362 with `gpl-data`;
  the irq fixture tail renders at rms 27 and 1067 respectively
  (`crates/sid-play/tests/fixture_render.rs`).
- Combined waveforms: the default tables are the bitwise AND of the pure waveforms,
  which differs from the measured tables. From
  `cargo test -p mos6581 --features gpl-data --test gap -- --nocapture`:
  `GAP st: rms 83.8 max 170 (of 255)`, `GAP p_t: rms 139.2 max 255 (of 255)`,
  `GAP ps_: rms 140.9 max 254 (of 255)`, `GAP pst: rms 84.4 max 170 (of 255)`.
- The default `pst` table equals `st` by construction, so the mutual-distinctness
  test cannot catch a pst to st fall-through in the default build. The `gpl-data`
  build covers it.
- Voice model: the default voice is a centred DAC, which differs from the measured
  asymmetric one. The gated test `the_output_is_asymmetric_as_the_hardware_is`
  covers the measured behaviour.
- Envelope timing: the rate periods are derived from the datasheet's nominal
  attack times rather than measured, and the decay/release curve uses its own
  breakpoints, so envelope lengths and the shape of the falling curve differ.
- ADSR delay bug: the rate counter does not skip zero on wrap
  (`ENV_RATE_COUNTER_SKIPS_ZERO` off), so the length of the delayed step after a
  rate rewrite differs.
- Resonance: an own Q model with a different range, so resonant peaks differ in
  height at every setting.
- Mixer DC: an own size and sign, so `$D418` sample playback sits at a different
  level relative to the voices and volume writes thump differently.
- Noise: different output bit selection and reset seed, so the noise spectrum and
  sequence differ.
- Power-on RAM in `sid-play`: an all-zero image instead of the captured pattern,
  so tunes that read uninitialised memory can start differently.

Candidate for the clean-room cutoff task: derive the closed corner from the
datasheet formula with the C64's actual filter capacitors (to be sourced from a
public schematic), not tuned to measured data.
